# ChatGPT Clone

A full-stack chat application that recreates the core experience of ChatGPT. Users can send questions, receive responses generated by Google Gemini, and view the conversation history loaded from a MySQL database.

## What It Does

- Provides a chat interface with a sidebar, header, message list, and message input.
- Loads previously stored conversation messages when the frontend starts.
- Sends user questions to an Express.js backend through the `/api/chat/conversations` endpoint.
- Stores user and assistant messages in MySQL.
- Sends recent conversation history to Gemini so responses have conversational context.
- Displays assistant responses as Markdown and supports syntax-highlighted code blocks.
- Shows a loading state while an assistant response is being generated.
- Records the assistant response token count in the database.

## How It Works

1. The React frontend requests saved messages from `GET /api/chat/conversations`.
2. When a user submits a question, the frontend optimistically displays it and sends it to `POST /api/chat/conversations`.
3. The backend validates and stores the question as a `user` message.
4. The chat service retrieves the latest conversation history and sends it to the configured Gemini model.
5. The generated response is stored as an `assistant` message, together with its token count.
6. The API returns both persisted messages, and the frontend replaces the temporary message with the saved user message and assistant response.

## Technologies Used

### Frontend

- React 19 for the user interface and component-based state management.
- Vite for development and production builds.
- Axios for HTTP requests to the backend API.
- `lucide-react` for interface icons.
- `react-markdown` for rendering assistant messages.
- `react-syntax-highlighter` for formatted code blocks in assistant responses.
- CSS and CSS Modules for component styling.

### Backend

- Node.js with ES modules.
- Express.js for the HTTP server and API routes.
- MySQL with `mysql2` for persistent conversation storage.
- Google GenAI SDK (`@google/genai`) for Gemini model responses.
- `cors` for cross-origin development requests.
- `dotenv` for loading environment variables.
- Nodemon for automatically restarting the backend during development.

## API Endpoints

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/api/chat/conversations` | Returns up to 100 saved conversation messages in chronological order. |
| `POST` | `/api/chat/conversations` | Validates and stores a question, generates an assistant response, and returns both messages. |

The `POST` endpoint expects a JSON body:

```json
{
	"question": "Explain how an Express.js route works"
}
```

## Getting Started

### Prerequisites

- Node.js and npm
- MySQL server
- A Google Gemini API key

### 1. Configure the database

Create a MySQL database and conversation table. The table definition is available in `Backend/db/schema.sql`. The SQL statement in that file is commented out, so uncomment and execute it in your MySQL client.

The application uses these database defaults unless environment variables override them:

### 2. Install dependencies

From the project directory, install dependencies for both applications:

```bash
cd Backend
npm install

cd ../frontend
npm install
```

### 3. Start the applications

Start the backend in one terminal:

```bash
cd Backend
npm run dev
```

The API runs at `http://localhost:5500`.

Start the frontend in a second terminal:

```bash
cd frontend
npm run dev
```

Vite serves the frontend and proxies `/api` requests to the backend at `http://localhost:5500`.

## Available Scripts

### Backend

- `npm run dev` starts the backend with Nodemon.
- `npm start` starts the backend with Nodemon.

### Frontend

- `npm run dev` starts the Vite development server.
- `npm run build` creates a production build.
- `npm run lint` runs ESLint.
- `npm run preview` previews the production build locally.

## Current Scope

This project currently focuses on a single persistent conversation stream. Authentication, multiple conversation threads, streaming responses, and voice input are not implemented yet.
